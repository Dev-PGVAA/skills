# Research Report

Produce a coherent report that helps its reader understand a domain or decide what to do. Depth comes from verified evidence, mechanisms, comparisons, and limits. There is no default minimum page count, word count, table quota, or mandatory formal voice.

## 1. Establish the deliverable

Use the user's topic, purpose, audience, scope, language, length, deadline, source restrictions, and output format. Infer ordinary choices from context; ask only about missing information that materially changes the report. Preserve existing structure when editing a supplied report.

A page target depends on font, margins, tables, and format. Set a provisional content budget if useful, then measure pages after rendering. Never promise 30 pages from a word count alone. If no file format is requested, a single Markdown report is a useful default for substantial work; an inline answer can suffice for a shorter report. Use available document/PDF skills for requested formats, with rendering and visual verification.

## 2. Build an evidence base

Use `deep-research` if available; otherwise follow this minimum protocol:

- Identify the decisive questions and plausible counter-evidence before collecting sources.
- Inspect original sources; capture claim, exact URL/document locator, date, scope, support, limitation, and confidence in a fact sheet in the working directory.
- Separate source authority from claim certainty. Official marketing supports what a company says, not necessarily what its product achieves. A–E labels describe provenance and cannot replace citations.
- Trace repeated claims to their underlying source; recycled reporting is not independent corroboration.
- Record units, denominators, periods, populations, methodology, and uncertainty for important figures. Recompute derived quantities and label assumptions and scenarios.
- Preserve contradictory evidence, unavailable sources, and gaps. Uncertainty does not justify inventing a range or a reassuring hedge.

A provisional outline may guide research; revise it when evidence changes the argument. Do not finish a decorative outline and then hunt only for supporting citations.

## 3. Architect and write

Choose sections that answer the actual questions. [Report structures](references/example-report.md) gives adaptable structures; [Policy and admissions analysis](references/example-report-usa.md) applies only to those domains.

Plan section budgets only for a substantial length target. Each section needs a distinct job, evidence, analysis, and connection to the decision. Remove irrelevant financial, legal, tooling, or catalog sections rather than filling them by habit. Use tables for like-for-like comparisons and prose for mechanisms, qualifications, and interpretation.

Draft progressively without overwriting user work. Link claims to their sources while drafting; delaying all citations to the end loses provenance. Keep terminology, entities, dates, definitions, and assumptions consistent across sections. Use the reader's requested register; concrete prose beats forced third person or dense jargon.

For long reports, a short executive summary can state the answer, strongest reasons, limits, and recommended action. Conclusions introduce no new unsupported facts. An overview may explain rather than recommend if the user asked for orientation.

## 4. Subagents for substantial reports

Delegate only meaningful independent work when supported and permitted. The parent owns scope, outline, source ledger, final file, and editorial voice.

- **Section researcher:** one nonoverlapping question or domain; returns claim records, source extracts/locators, relevant mechanisms, contradictions, and gaps. Do not ask several agents to write the whole report.
- **Quantitative verifier:** selected tables, raw inputs, definitions, and formulas; checks units, arithmetic, comparability, and sensitivity without changing the recommendation.
- **Independent reviewer:** user brief, draft, and raw sources; checks whether conclusions follow, important alternatives were omitted, citations entail claims, and length creates repetition. Avoid priming with the desired verdict.

Give each assignment a boundary, inputs, output file or return schema, effort limit, permitted actions, and stop condition. Agents use separate scratch files and never overwrite the final report. The parent independently inspects decisive sources, reconciles overlaps and contradictions, and integrates one coherent report. No recursive fanout by default. Run these passes sequentially if agents are unavailable or the task is small.

## 5. Verify and deliver

- Check every recommendation-driving claim and every important quantitative table cell against its source and fact sheet. Spot-check remaining factual prose according to risk; do not claim exhaustive verification if only sampled.
- Verify each citation actually supports the adjacent wording, with source date and version when material. Keep readable linked citations or the user's requested citation style; source category is optional metadata.
- Look for inconsistent definitions, duplicated sections, omitted alternatives, false precision, and conclusions stronger than the evidence.
- Confirm requested scope, language, length, structure, and format. For page-based output inspect rendered pages for clipped tables, broken headings, missing glyphs, blank pages, and citation legibility. Report any rendering limitation.
- Remove padding: repeated summaries, generic background the audience already knows, tables that duplicate prose, and artificial catalogs. If evidence cannot support requested depth, disclose the gap and develop useful mechanism analysis without inventing facts.
- Deliver the usable report with a brief note on its scope and material limitations. Working fact sheets remain internal unless requested or needed for reproducibility.
